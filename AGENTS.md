# AGENTS.md: se2-modkit

Instructions for AI coding tools (Codex, Cursor, Claude Code and others), and a short orientation for people.

Shared build tooling for Space Engineers 2 mods: environment discovery, Blender-to-game model pipeline, SDK build, validation and tests. GPL-3.0.

## Layout

- `src/se2modkit/` the Python package (`compat.py` and `compat.toml` hold the supported game versions).
- `tests/` is pytest. `THIRD_PARTY.md` lists third-party material. `README.md`.

## Build and test

```bash
pip install -e .[dev]
python -m pytest -q          # offline tests
ruff check .
```

`scripts/test.sh` runs the offline checks. CI runs the same on GitHub-hosted runners, which have no game, SDK or Blender.

## Code style

- Python 3.11+. 4 spaces, 120 columns, type hints as in the neighboring code. The core package depends on `numpy` only.
- Fail with one plain sentence naming what is missing and how to set it; never a traceback for a missing game, SDK or Blender.

## Rules for this repo

- The supported game versions live in `src/se2modkit/compat.toml`; update it together with the README after verifying a new game build.
- Paths go through `pathlib`; text files are written with `\n` newlines.
- Never hard-code a machine-specific path as a default.

## Commits

- Conventional Commits: `type(scope): summary` (feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert). The changelog is generated from them with git-cliff (`scripts/changelog.sh`).
- Sign off with `git commit -s`. The project is GPL-3.0; outside contributors also sign the Rioku Labs CLA once (`CLA.md` in riokulabs/.github), which the `cla` workflow checks. Never add `actions/checkout` or any step that runs pull request code to `.github/workflows/cla.yml`.
- Optional hooks: `scripts/install-hooks.sh`.

## Never

- Never add AI attribution: no `Co-Authored-By` trailer for an AI tool, no "generated by/with" notes in commits, pull requests, code or docs.
- Never commit decompiled Keen code, game binaries, Keen assets beyond the vanilla reuse this repo documents, or third-party content without a license.
- Never commit secrets or tokens (API tokens, Steam or GitHub credentials, `.env` files).
- Never push, tag or publish (GitHub, Steam Workshop, deploys) unless the maintainer asked for it.
- Never modify the game install or the Steam library directories.
- Never commit game files, decompiled code, Keen type data or baselines.
- Never add code that stores, logs or requests Steam credentials or tokens.
- Never rewrite published history or force-push shared branches.
